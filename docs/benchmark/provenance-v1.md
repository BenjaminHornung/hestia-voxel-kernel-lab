# Benchmark Provenance v1

JSON contracts use strict RFC 8785-style JCS bytes: UTF-8 without BOM, no trailing LF, raw UTF-16 property-key order, preserved arrays, and no Unicode normalization. Duplicate keys are rejected before parsing. Nonfinite, negative-zero, unsafe, cyclic, accessor, non-simple, and unpaired-surrogate values fail closed.

Relative bundle paths are lowercase ASCII POSIX paths. Fileset, build, and bundle SHA-256 values use versioned domains and length-prefixed frames. `bundle.sha256` is the only digest-cover exception. Streaming verification uses the immutable v1 limits: 5,000 ms Git commands, 1 MiB individual and combined command output, at most 4,096 files, 64 MiB per file, 512 MiB aggregate bytes, and 64 KiB digest chunks; callers may tighten but never widen them. Verification rejects missing, extra, duplicate, symlink, special, or tampered files and never repairs a partial bundle. Raw runs, telemetry exports, and validation receipts use `application/json` plus `jcs-rfc8785`; each logical run has exactly one nested raw-run, telemetry, and receipt binding. Bundle run entries are canonically ordered by `runId`; reversed order is invalid. The supported trace artifact tuple is path suffix `traces/**/trace.json.gz`, media type `application/gzip`, and `binary-exact` serialization; `heap-snapshot` and `gpu-capture` remain fail-closed and unavailable until an evidence-backed extension/media tuple is standardized.

Source preflight measures the current verified checkout commit/tree, exact clean porcelain-v2 status bytes, verified real repository root, available fixture/candidate filesets, and current build fileset through an injectable fixed-argument command runner. Root comparison is case-insensitive only on Windows; repository source paths preserve exact case. The c64 commit `c64aeef1f51dd0ed2d8431411cf3ba1e84195b9d` is the historical WP04 fixture owner only: its exact path list and fileset digest `sha256:5a89e11f59c2fbe1d35eaa782aed039505edbc45282302698ad4009fb04900e0` are read from bounded Git blobs, not from the current checkout. Preflight returns a node-only build handoff with resolved root identity and rehashes that handoff immediately before return; consumers verify it again before preview/server start. It promotes only byte-verified semantic, path, and fileset bindings: semantic observation requires canonical fixture-contract bytes whose SHA-256 matches the supplied digest. Declared claims are never returned as observed evidence without that verification. Future owner-bound sources use unavailable structural bindings rather than fabricated SHA/path values. A validation receipt accepts actual telemetry/run/schema/registry/validator-source inputs and an injected accepted BR02 adapter, derives each target iteration from the actual telemetry object, and binds the adapter contract literals, canonical registry, target run/binding, exact telemetry bytes, complete ordered adapter-result digest, ordered raw-sample projection, and positive sample count in closed `benchmark-telemetry-derivation-evidence-v1`. The validator source commit/fileset fields are integrity bindings for the supplied validator bytes, not source-authenticity or authorship evidence. Both evidence and receipt are deterministic and self-excluding; the provenance chain attests integrity of the supplied derivation, not adapter source code or code execution. No timestamp or random identifier is allowed. Receipts are not created for invalid or mismatched derivations.

The three normative documentation paths are `docs/benchmark/contracts-v1.md`, `docs/benchmark/provenance-v1.md`, and `docs/benchmark/third-party-ajv.md`; C08/source-pack documentation remains read-only input. Bundle timestamps require an exact real-calendar UTC roundtrip, not only a lexical date pattern. H2/H3 device selection, external attestation, immutable storage, and real performance-gate publication remain owner-bound residuals. Structurally representable profiles without observed bindings are never performance-eligible. BR01 makes no runtime, browser, timing, aggregation, or performance claim.

Source and fixture provenance are separate integrity axes: the current repository source commit is observed from the verified checkout, while a historical fixture binding is verified against its accepted commit/blob bytes and fileset. A current-source change therefore cannot silently rewrite historical fixture provenance, and a fixture-source change cannot silently rewrite current-source identity. These bindings establish integrity of supplied bytes; they do not authenticate authorship or execution.

Current candidate provenance is additionally bound to exact-case regular blob entries in the current `HEAD`. Git's clean-filter hash proves checkout equivalence before raw candidate fileset bytes are streamed; the HEAD membership, filtered hash, and raw digest are repeated before candidate bindings become observed. This is separate from the historical WP04 c64 blob binding.
